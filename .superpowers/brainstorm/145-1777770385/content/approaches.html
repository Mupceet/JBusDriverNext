实现方案对比

三种方式组织列表/网格双模式

A

MovieList 参数化（推荐）

MovieList 增加 isGrid: Boolean 参数，内部根据参数选择 LazyColumn 或 LazyVerticalGrid。MovieItem 也增加同一参数切换横/竖布局。

优点

  • 改动最小，复用现有的加载更多逻辑
  • 各页面只需传入 isGrid 参数
  • List/Grid 的分页、空状态等逻辑保持一致

缺点

  • MovieList 和 MovieItem 内部有 if/else 分支
B

独立组件拆分

新建 MovieGridItem 和 MovieGridList 组件，与现有的 MovieItem/MovieList 并列。各页面根据模式选择用哪组组件。

优点

  • 每个组件职责单一，无分支逻辑
  • 可以独立演进，不受对方影响

缺点

  • 重复代码：加载更多、空状态、item key 逻辑要复制一份
  • 四个消费页面都要加 if/else 选择组件
C

布局策略抽象

抽象出 ListLayoutStrategy 接口，封装 LazyColumn 和 LazyVerticalGrid 的差异。MovieList 通过策略对象切换。

优点

  • 最"干净"的抽象，理论上扩展性好

缺点

  • LazyColumn 和 LazyVerticalGrid API 差异较大，抽象层会很厚
  • 只有两种模式，过度设计
